DATABASE SCHEMA DETAILS
================================================================================

TABLE STRUCTURE:

1. customers
   - Primary customer accounts
   - Fields: id, email, name, company, tier, status, timestamps
   - Indexes: email (unique), status, created_at
   - Foreign key: Used by all other tables

2. customer_automations
   - Automation workflows per customer
   - Fields: customer_id, n8n_workflow_id, automation_type, status, configuration
   - Indexes: customer_id, n8n_workflow_id, status
   - Types: email, sms, call, webhook, custom

3. oauth_tokens
   - OAuth credentials (encrypted storage)
   - Fields: customer_id, provider, access_token, refresh_token, expires_at
   - Encryption fields: access_token_encrypted, refresh_token_encrypted
   - Providers: google, hubspot, twilio
   - Unique: (customer_id, provider)

4. call_recordings
   - Twilio call recordings
   - Fields: call_sid, recording_url, transcript, insights_json, duration_seconds
   - Status: pending, processing, completed, failed
   - Encrypted fields: transcript_encrypted

5. execution_logs
   - Workflow execution history
   - Fields: workflow_id, executed_at, status, result_json, error_message
   - Duration tracking: duration_ms, retries
   - Status types: success, failed, pending, timeout

6. support_tickets
   - Customer support management
   - Fields: title, message, status, priority, assigned_to, resolved_at
   - Status: open, in_progress, closed, on_hold
   - Priority: low, normal, high, critical

7. subscriptions
   - Stripe subscription management
   - Fields: stripe_subscription_id, tier, status, current_period_*
   - Status: active, cancelled, past_due, incomplete
   - Linked to: billing_history

8. billing_history
   - Payment records
   - Fields: amount, currency, status, stripe_charge_id, stripe_invoice_id
   - Status: pending, paid, failed, refunded
   - Linked to: subscriptions, customers

9. automation_stats
   - Performance metrics per automation
   - Fields: emails_sent, emails_opened, calls_made, calls_answered, etc.
   - Updated_at: Real-time statistics
   - Unique: automation_id (one row per automation)

10. api_usage
    - API request tracking
    - Fields: endpoint, method, status_code, response_time_ms, ip_address
    - For monitoring and analytics

11. audit_logs
    - Complete action audit trail
    - Fields: action, resource_type, resource_id, changes (JSONB)
    - For compliance and debugging

12. system_config
    - System-wide configuration
    - Key-value store with type information
    - Examples: api_version, database_version, maintenance_mode

ERROR HANDLING FRAMEWORK
================================================================================

ERROR CODES (13 TYPES):

Client Errors (4xx):
- INVALID_REQUEST (400) - Malformed request
- UNAUTHORIZED (401) - Missing authentication
- FORBIDDEN (403) - Insufficient permissions
- NOT_FOUND (404) - Resource not found
- CONFLICT (409) - Resource conflict
- VALIDATION_ERROR (400) - Data validation failure
- RATE_LIMITED (429) - Too many requests

Server Errors (5xx):
- INTERNAL_ERROR (500) - Unexpected error
- DATABASE_ERROR (500) - Database operation failed
- STRIPE_ERROR (500) - Stripe API error
- N8N_ERROR (500) - n8n API error
- TWILIO_ERROR (500) - Twilio API error
- OAUTH_FAILED (400) - OAuth flow error
- SERVICE_UNAVAILABLE (503) - Service down

USAGE:
// Async route handler auto-catches errors
app.post('/api/endpoint', asyncHandler(async (req, res) => {
  throw ErrorFactory.validationError('Email required');
}));

// Custom errors
throw new AppError('CUSTOM', 'Message', 400, {details});

// Automatic logging with context
// Error appears in console with timestamp, endpoint, user ID
